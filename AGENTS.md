# AGENTS.md — canopen-interop

## What this is

Independent CANopen implementations (CANopenNode, Lely, python-canopen) in containers behind one command-line contract, with deterministic EDS/DCF fixtures, used as oracles by go-canopen and canopenctl. Nothing here depends on go-canopen. Profile: **interoperability**.

## Organisation standards

This repository follows **otfabric/engineering policy 1.1**, profile **interoperability** (`.otfabric/policy.yaml`, mode `enforce`; exceptions in `.otfabric/exceptions.yaml`). Where this file and the organisation standards disagree, this file wins here — say so in your report.

## Where the truth lives

| Question | Source |
|---|---|
| Container commands, documents, exit codes | docs/CONTAINER_CONTRACT.md (`contract_version` in versions.yaml) |
| What each stack can do | docs/CAPABILITIES.md, `make capabilities` |
| Pins (upstream revision, source hash, base image digests, published?) | versions.yaml — checked against Dockerfiles by `scripts/check-versions.sh` |
| Fixtures | fixtures/eds, generated by `scripts/gen-eds-fixtures.py` (docs/FIXTURES.md) |
| Expected deviations of the stacks | tests/known-differences.tsv |
| Results | docs/COMPATIBILITY.md, reports/ (self-test) |

## Hard rules

1. Nothing floats: upstream sources by commit + `source_sha256`, base images by digest. `make validate` must pass.
2. Skips and known differences are never counted as passes; a known difference needs evidence in tests/known-differences.tsv.
3. An adapter answers an unsupported operation with the contract's `unsupported` error, never with a fake success.
4. Contract changes bump `contract_version` and are reflected in every adapter and in docs/CONTAINER_CONTRACT.md in the same change.
5. Licences: every redistributed component in THIRD_PARTY_NOTICES.md and `licenses/`; images that may not be redistributed are not published (`published:` in versions.yaml).
6. The release tag equals `interop_version`; bump versions.yaml before tagging.

## Commands
