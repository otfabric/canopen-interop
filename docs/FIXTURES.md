# Fixtures

All fixtures are in [`fixtures/`](../fixtures) and in every image under
`/fixtures` (`print-fixture eds/interop-device.eds`). The EDS/DCF files are
generated by [`scripts/gen-eds-fixtures.py`](../scripts/gen-eds-fixtures.py)
(CRLF line endings, as CiA 306 tools write them); `make fixtures-check` fails
when a committed file differs from the generator. Change the generator, not
the files.

## `fixtures/eds/interop-device.eds`: the shared test device

A CiA 306 EDS (EDSVersion 4.0) of the device every `device` adapter runs and
go-canopen's tests address (node-ID 5 in the self-test). Valid for Lely's
dcfchk and for python canopen's importer; the canopennode image compiles its
object dictionary from it with CANopenEditor.

Design notes:

* **0x2004** has a 64-character default because CANopenNode sizes a string
  object by its default value; downloads of exactly 64 characters behave the
  same on every stack (shorter strings: see LIMITATIONS.md).
* **0x2005** is a DOMAIN, not an OCTET_STRING: the stacks disagree on how
  to write an octet string default (CANopenEditor: space-separated bytes;
  lely: hex without spaces) and on whether a shorter download is allowed.
  The canopennode device backs it with a 4096-byte application buffer.
* **REAL defaults are 0**: Lely reads a REAL32 `DefaultValue` as the IEEE bit
  pattern (`0x3FC00000`), python canopen and CANopenEditor as a decimal
  (`1.5`); 0 means the same to all of them.
* **0x200A** exercises range aborts (0x06090031/0x06090032); only lely checks
  limits (`deviceLimits`).
* The device boots into pre-operational and waits for NMT start.
* **LSS (1.1)**: `[DeviceInfo] LSS_Supported=1` (lely creates its LSS slave
  only then); the LSS address is 0x1018: vendor-ID 0, product code
  0x434F4931 ("COI1"), revision 0x00010000 and the serial number, 1 or
  `device --serial`.
* **0x1007 (1.1)** lets the rpdo suite set a SYNC window by SDO.

Fixture schema 1.1 (canopen-interop v0.2.0) added 0x1007 and
`LSS_Supported=1` to the shared device and its DCF, and the two fixtures
below; nothing was removed or renumbered.

## `fixtures/eds/mpdo-device.eds` (1.1)

The shared device plus an object scanner list 0x1FA0 (ARRAY of 4
UNSIGNED32, SAM-MPDO producer) and an object dispatching list 0x1FD0
(ARRAY of 4 UNSIGNED64, SAM-MPDO consumer), all 0. `mpdo-send` and
`mpdo-receive` (lely) run it with TPDO 1 / RPDO 1 configured as the MPDO
and the lists filled from the flags.

## `fixtures/eds/interop-device-other-product.eds` (1.1)

The shared device with product code 0x434F4932 ("COI2", 0x1018:02 and
`ProductNumber`): `boot --slave N:/fixtures/eds/interop-device-other-product.eds`
expects that product code (0x1F86) of a device that has 0x434F4931, so the
'boot slave' process ends with error status M.
